# symbol-web

Веб-приложение на Go, которое превращает текст в ASCII-арт: графическая (GUI) версия проекта **symbol-art**. Дополнительно в нём есть AI-функции: подсказки текста от настоящей LLM, рекомендация баннера по правилам и креативные варианты текста.

## Описание (Description)

### Обзор проекта

Пользователь вводит текст на странице, выбирает один из трёх баннеров (шрифтов) — **standard**, **shadow** или **thinkertoy** — и получает ASCII-арт прямо на главной странице. По мере ввода появляются AI-подсказки, а отдельные кнопки помогают выбрать баннер и придумать варианты текста.

### Функции

**Основное приложение**
- `GET /` — главная страница с формой (Go-шаблоны);
- `POST /symbol-art` — генерация ASCII-арта; результат показывается на главной странице под формой, введённый текст и выбранный баннер сохраняются;
- многострочный текст (Enter в поле ввода);
- проверка ввода и коды ответов из ТЗ: 400, 404, 405, 500, 503;
- форма работает и без JavaScript.

**AI-функции**
- **Подсказки текста** (`/api/suggest`, обязательно) — продолжения вводимого текста от LLM; появляются в выпадающем списке через 300 мс после остановки ввода;
- **Рекомендация баннера** (`/api/recommend-banner`, обязательно) — на правилах, без LLM; использует профилирование баннеров из проекта symbol-fs;
- **Креативные варианты** (`/api/variations`, бонус) — 3–5 вариантов текста в разных стилях, у каждого предложенный баннер;
- **Mock-режим** — без настроенной LLM подсказки и варианты приходят из детерминированных заготовок, поэтому проект запускается и проверяется без API-ключа;
- **Кэш** (бонус) — успешные ответы LLM хранятся в памяти 5 минут.

### Технологии

| Часть | Технологии |
|---|---|
| Бэкенд | Go 1.21+, только стандартная библиотека (`net/http`, `html/template`, `encoding/json`) |
| Фронтенд | HTML, CSS, JavaScript (ES-модули, `fetch`) без фреймворков и сборщиков |
| LLM | любой OpenAI-совместимый API: локальная [Ollama](https://ollama.com) (рекомендуется, бесплатно), OpenAI, Groq и др. |
| Тесты | `testing`, `net/http/httptest`; фронтенд проверялся в headless Chrome |

## Запуск (Usage: How to Run)

### Требования

- **Go 1.21 или новее** (проверено на Go 1.25). Проверить: `go version`;
- **API-ключ не нужен**: без настроенной LLM приложение работает в mock-режиме;
- для настоящих AI-подсказок (по желанию) — [Ollama](https://ollama.com/download) с моделью, например `llama3.2`, или ключ любого OpenAI-совместимого сервиса.

### Установка

```bash
git clone https://01.tomorrow-school.ai/git/adulmaev/symbol-web
cd symbol-web
```

Внешних зависимостей нет: `go.mod` использует только стандартную библиотеку.

### Настройка окружения

Настройки читаются из переменных окружения. Удобнее всего хранить их в файле `.env`: сервер читает его при старте.

```bash
cp .env.example .env
```

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | порт веб-сервера |
| `LLM_BASE_URL` | *(пусто)* | адрес LLM API. **Пусто — mock-режим** |
| `LLM_MODEL` | *(пусто)* | имя модели; обязательно, если задан `LLM_BASE_URL` |
| `LLM_API_KEY` | *(пусто)* | ключ для облачных сервисов (для Ollama не нужен) |

Переменные, заданные в терминале, важнее значений из `.env`. Файл `.env` не попадает в git.

### Запуск сервера

**Запускайте из корня проекта**: сервер ищет `templates/`, `static/` и файлы баннеров относительно текущей папки.

```bash
go run ./cmd/server
# или
go run cmd/server/main.go
```

В логе появится:

```
banner standard   average width 7.59 (standard)
banner shadow     average width 8.69 (wide)
banner thinkertoy average width 5.06 (compact)
LLM mode: mock (LLM_BASE_URL is not set, canned answers)
Server running on http://localhost:8080
```

Остановка: **Ctrl+C**. Сервер дожидается завершения начатых запросов (graceful shutdown).

> Если появляется `bind: address already in use`, порт 8080 занят другой программой. Укажите другой: `PORT=8081 go run ./cmd/server` или `PORT=8081` в `.env`.

### Открыть в браузере

http://localhost:8080 (или ваш `PORT`).

### Тесты

```bash
go test ./...          # все тесты
go test -race ./...    # с детектором гонок данных
go vet ./...
```

### Алгоритм генерации ASCII-арта

**Формат баннера.** Файл баннера описывает 95 печатных символов ASCII от пробела (32) до `~` (126) по порядку. Каждый символ занимает блок из 9 строк: пустая строка-разделитель и 8 строк рисунка.

**Загрузка** (`ascii.LoadFont`). Файл читается построчно и собирается в `Font` — словарь `map[rune][8]string` «символ → 8 строк рисунка». Файл с недостающими символами или обрезанным блоком отклоняется с ошибкой.

**Рендер** (`ascii.Render`):
1. текст делится по `\n` на строки;
2. каждая строка текста превращается в блок из 8 строк арта: для каждой буквы её строка 0 дописывается в итоговую строку 0, строка 1 — в строку 1 и т.д. (`strings.Builder`), так буквы встают рядом;
3. блоки ставятся друг под другом; любая серия пустых строк текста даёт ровно одну пустую строку арта.

**Проверки** (`ascii.ValidateText`): текст не пустой, не длиннее 1000 символов, содержит только печатные ASCII-символы и переводы строк. Имя баннера сверяется с белым списком, что защищает от path traversal (`../../etc/passwd`). Переводы строк Windows (`\r\n`), которые присылает браузер, приводятся к `\n`.

**Кэш шрифтов.** Разобранный шрифт хранится в памяти. На каждый запрос выполняется только дешёвый `os.Stat`: изменённый файл перечитывается, удалённый даёт 404 без перезапуска сервера. Так же кэшируются шаблоны.

### Архитектура бэкенда

- **Маршрутизация**: `http.ServeMux` в `handlers.Routes`. Метод запроса проверяется в каждом обработчике (405 и заголовок `Allow` при неверном методе);
- **Middleware**: `logRequests` (метод, путь, статус, длительность) и `recoverPanics` (паника в обработчике превращается в ответ 500, а не в оборванное соединение);
- **Интерфейсы**: обработчики зависят от интерфейсов `ArtGenerator`, `BannerRecommender`, `Assistant`, а не от конкретных типов. `main` выбирает реализацию: `ai.Mock` или `ai.Client`;
- **Безопасность**: `html/template` экранирует весь вывод (защита от XSS); размер тела запроса ограничен 64 КБ; у сервера заданы таймауты чтения, записи и простоя;
- **Ответ сначала собирается в буфер**: если шаблон упадёт посередине, клиент получит честный 500, а не половину страницы с кодом 200.

### Документация API

Все AI-эндпоинты принимают `POST` с телом `{"text": "..."}` (`Content-Type: application/json`) и возвращают JSON. Ошибки всегда приходят в виде `{"error": "понятное сообщение"}`.

#### `GET /` — главная страница
HTML-страница с формой. `200 OK`.

#### `POST /symbol-art` — генерация ASCII-арта
Обычная HTML-форма (`application/x-www-form-urlencoded`), поля `text` и `banner`. Возвращает главную страницу с результатом под формой.

| Ситуация | Код |
|---|---|
| успех | `200` |
| пустой текст, длиннее 1000 символов, недопустимый символ, неизвестный баннер | `400` (сообщение показывается рядом с формой) |
| файл баннера или шаблона не найден, неизвестный путь | `404` |
| неверный метод | `405` |
| ошибка шаблона или внутренняя ошибка | `500` |

#### `POST /api/suggest` — подсказки текста (LLM)
```json
// запрос
{ "text": "Happy Birth" }
// ответ 200 (mock-режим)
{ "suggestions": ["Happy Birth!", "Happy Birth World", "~ Happy Birth ~", "HAPPY BIRTH"] }
```
Заголовок ответа `X-LLM-Mode: mock` или `live` показывает, откуда ответ.

#### `POST /api/recommend-banner` — рекомендация баннера (правила, без LLM)
```json
// запрос
{ "text": "WELCOME" }
// ответ 200
{
  "recommended": "shadow",
  "reasoning": "Bold, uppercase text works best with shadow for maximum impact and readability.",
  "alternatives": [
    { "banner": "standard",   "score": 0.7, "reason": "Good alternative, slightly less impactful" },
    { "banner": "thinkertoy", "score": 0.4, "reason": "Too decorative for uppercase text" }
  ]
}
```

#### `POST /api/variations` — креативные варианты (LLM, бонус)
```json
// запрос
{ "text": "hello" }
// ответ 200 (mock-режим)
{
  "variations": [
    { "text": "Hello.",    "description": "Professional, formal style", "suggested_banner": "standard" },
    { "text": "HELLO!",    "description": "Bold, attention-grabbing",   "suggested_banner": "shadow" },
    { "text": "hello :)",  "description": "Friendly, casual style",     "suggested_banner": "standard" },
    { "text": "~ hello ~", "description": "Friendly, decorated style",  "suggested_banner": "thinkertoy" }
  ]
}
```

#### Коды ответов API

| Код | Когда |
|---|---|
| `200` | успех |
| `400` | пустой текст; для `/api/suggest` меньше 3 символов; больше 1000 символов; недопустимый символ; тело не JSON или больше 64 КБ |
| `404` | неизвестный путь `/api/...` |
| `405` | метод не `POST` |
| `500` | LLM ответила, но непригодно (даже после повторной попытки), или ошибка запроса к LLM (неверная модель или ключ) |
| `503` | LLM недоступна: сервер не отвечает, таймаут 10 секунд, перегрузка (HTTP 429/5xx) |

Подробности ошибок LLM пишутся в лог сервера, пользователь получает понятное сообщение. Сбой LLM никогда не роняет сервер.

### Архитектура фронтенда

- **Прогрессивное улучшение**: форма и генерация работают без JavaScript; JS только добавляет AI-функции;
- **ES-модули** (`<script type="module">`): по одному модулю на функцию плюс `shared.js` с общей функцией `postJSON`, через которую идут все запросы к API и которая одинаково превращает ошибки сети и API в понятные сообщения;
- **AJAX через `fetch`**: AI-функции обмениваются с сервером JSON в фоне и меняют только часть страницы, без перезагрузки;
- **Безопасность**: текст от сервера и LLM вставляется только через `textContent`, никогда через `innerHTML` (защита от XSS);
- **Доступность**: подписи у полей, ARIA-атрибуты у выпадающего списка, модальное окно на элементе `<dialog>` (Escape, фокус внутри окна), карточки вариантов — кнопки, доступные с клавиатуры.

| Модуль | Что делает |
|---|---|
| `suggestions.js` | debounce 300 мс, минимум 3 символа, выпадающий список, выбор мышью или клавишами ↑ ↓ Enter, Escape; устаревшие запросы отменяются через `AbortController` |
| `recommendations.js` | кнопка «🤖 AI Recommend Banner»: состояние загрузки, причина и альтернативы с оценками, подсветка рекомендованного баннера, кнопка «Use …» |
| `variations.js` | кнопка «💡 Get Creative Ideas»: модальное окно с вариантами; выбор подставляет текст и выбирает баннер |

## AI-функции (AI Features)

### Подсказки текста (`/api/suggest`)

1. Пользователь печатает; через 300 мс после последнего нажатия, если введено не меньше 3 символов, фронтенд отправляет текст на сервер.
2. Сервер подставляет текст в промпт из ТЗ (`%q` экранирует кавычки, что защищает от подмены инструкций) и отправляет его LLM с таймаутом **10 секунд**.
3. **Ответ LLM проверяется**, прежде чем попасть на фронтенд: убираются нумерация, маркеры, кавычки и вводные фразы («Here are some ideas:»); каждая строка склеивается с введённым текстом (модели часто возвращают только продолжение: `World` для `Hello w` → `Hello world`); отбрасываются строки, которые не продолжают ввод, добавляют больше 50 символов или содержат символы, которые нельзя нарисовать баннером.
4. Если пригодных подсказок меньше 3, LLM спрашивают ещё раз (обе попытки укладываются в общие 10 секунд).
5. Успешный ответ кэшируется на 5 минут: повторный ввод того же текста возвращается мгновенно.

### Система рекомендации баннера (`/api/recommend-banner`)

Работает **только на правилах**: без LLM, без ключа и без сети, поэтому всегда доступна. Оценка каждого баннера:

```
score = соответствие стилю × соответствие ширине
```

**Соответствие стилю** определяется правилами по профилю текста (регистр, длина, спецсимволы), как в анализаторе symbol-art. Правила проверяются по порядку, срабатывает первое:

| # | Условие | Лучше всего подходит |
|---|---|---|
| 1 | много спецсимволов (≥ 30%, минимум 2) | thinkertoy — игривый стиль |
| 2 | все буквы заглавные | shadow — жирный, заметный |
| 3 | не больше 6 символов | shadow — короткий текст выделяется |
| 4 | 13 символов и больше или несколько строк | standard — читаемый |
| 5 | всё остальное | thinkertoy — короткий смешанный текст |

**Соответствие ширине** использует профилирование баннеров из symbol-fs: при старте измеряется средняя ширина 95 символов каждого баннера (в колонках) и определяется стиль:

| Баннер | Средняя ширина | Стиль |
|---|---|---|
| thinkertoy | 5.06 | compact (< 6) |
| standard | 7.59 | standard (6–8.5) |
| shadow | 8.69 | wide (> 8.5) |

Ширина арта оценивается как «самая длинная строка × средняя ширина буквы». Если результат не помещается в 80 колонок, оценка уменьшается пропорционально (`80 / ширина`). Например, для «Hello wonderful world of ASCII» (30 символов) shadow дал бы около 261 колонки и получает оценку 0.12, а для короткого «WELCOME» ширина не мешает, и ответ совпадает с примером из ТЗ. Правила детерминированы: одинаковый текст всегда даёт одинаковую рекомендацию.

### Креативные варианты (`/api/variations`)

LLM получает промпт из ТЗ (4 стиля: формальный, жирный, дружелюбный, декоративный) с точной схемой JSON. Сервер вырезает JSON-массив из ответа (модели часто оборачивают его в ```` ```json ```` и пояснения), проверяет каждый вариант (непустой текст до 50 символов из ASCII) и заменяет неизвестный баннер на `standard`. Возвращается 3–5 вариантов. Выбор варианта подставляет текст и выбирает предложенный баннер.

### Mock-режим

Если `LLM_BASE_URL` не задан, вместо LLM работает `ai.Mock`: подсказки и варианты собираются по фиксированным шаблонам из введённого текста (`text + "!"`, `text + " World"`, `"~ " + text + " ~"`…), без сетевых запросов. Ответы детерминированы, поэтому проект можно запустить и проверить без API-ключа. Mock-режим — это нормальный режим работы, а не ошибка; на странице он помечен строкой «Mock mode: canned suggestions». Заготовки не «понимают» язык, поэтому для `Hell` mock предложит `Hell World`, а не `Hello`: осмысленные подсказки даёт только настоящая LLM.

### Настройка LLM

Подходит любой OpenAI-совместимый API (`/v1/chat/completions`).

**Ollama (локально, бесплатно, рекомендуется):**
1. Установите приложение с https://ollama.com/download и запустите его (сервер Ollama работает на `localhost:11434`).
2. Скачайте модель: `ollama pull llama3.2`
3. В `.env`:
   ```
   LLM_BASE_URL=http://localhost:11434
   LLM_MODEL=llama3.2
   ```
4. Перезапустите сервер: в логе появится `LLM mode: live (model "llama3.2")`.

Первый запрос может занять больше времени (модель загружается в память) и при превышении 10 секунд вернёт 503; повторите запрос.

**Облачные сервисы** (нужен ключ):

| Сервис | `LLM_BASE_URL` | Пример `LLM_MODEL` |

## Пример использования (Usage Example)

### Сервер

```bash
# Mock-режим (LLM не настроена): LLM-эндпоинты возвращают заготовленные ответы
$ go run ./cmd/server
Server running on http://localhost:8080

# Live-режим: указываем LLM, например локальную Ollama
$ export LLM_BASE_URL="http://localhost:11434"
$ export LLM_MODEL="llama3.2"
$ go run ./cmd/server
```

### Веб-интерфейс

1. Откройте http://localhost:8080.
2. Введите текст, например «Hello».
3. Через мгновение под полем появятся AI-подсказки; выберите одну мышью или клавишами ↑ ↓ и Enter.
4. Нажмите **🤖 AI Recommend Banner**: появится рекомендация с объяснением, рекомендованный баннер отметится ★, кнопка «Use …» выберет его.
5. По желанию нажмите **💡 Get Creative Ideas** и выберите вариант: подставятся текст и баннер.
6. Выберите баннер (или используйте рекомендацию) и нажмите **Generate**.
7. ASCII-арт появится под формой.

### API из терминала

```bash
curl -X POST http://localhost:8080/api/suggest \
     -H "Content-Type: application/json" -d '{"text": "Happy Birth"}'

curl -X POST http://localhost:8080/api/recommend-banner \
     -H "Content-Type: application/json" -d '{"text": "WELCOME"}'

curl -X POST http://localhost:8080/api/variations \
     -H "Content-Type: application/json" -d '{"text": "hello"}'

curl -X POST http://localhost:8080/symbol-art -d 'text=Hello&banner=shadow'
```
